## 要做的事（全部寫進 `docs/reports/039a-結果.md`）

1. **模組清單表**：`src/core/` 下每個計算模組一列：檔案路徑、一句話用途、行數、讀取哪些資料表（`src/data/` 的檔案）、直接依賴哪些其他模組、是否使用 RDKit.js（哪幾個函式：SMARTS 配對、環判定、分子量等）、對應的測試檔與測試數。
2. **依賴關係**：用文字樹或表格列出模組之間的依賴，標出「核心鏈」（新模組會用到的：VW、Va、莫耳體積與密度、Tg、CTE、自由體積、相對 Tg）的順序。
3. **RDKit 風險清單**：Python 的 RDKit 與目前網頁版 RDKit.js 版本可能不同。列出所有依賴 RDKit 行為的地方（SMARTS 配對、環與芳香性判定、SMILES 正規化等），各舉一個現有測試，標明搬遷後最可能產生差異的項目，以及 Python 端要如何固定版本（寫出目前 RDKit.js 的實際版本，從套件檔查，不憑記憶）。
4. **黃金資料方案**：提出如何把 TypeScript 的輸出匯出成 Python 可比對的檔案（例如每個模組一個 JSON：輸入、輸出、數值容差），列出每個核心鏈模組需要的輸入集合（取自現有測試與 `docs/verification/` 的輸出文件）。只提方案，不實作。
5. **搬遷順序與卡片清單**：依核心鏈順序，列出建議的搬遷任務卡（每個模組一張，包含預估範圍：行數、資料表、測試數、風險），並標出哪些可以和哪些同時做。
6. **即時回饋類小計算**：標出會在使用者輸入時即時觸發的計算（例如分子量、基本檢查），建議留在 TypeScript 或搬走，並說明依據。
7. **不確定的地方**：任何看不出來的依賴、沒有測試的模組、測試數與模組不對應的情況，逐項列出，不要猜。
