# 任務 P7-1A：反應規則 A 批（環氧與酚醛體系）（PLAN 7.1，D65）

編號：P7-1A
建立日期：2026-11-17
指派給：Claude Code

## 目標

`src/data/reaction_rules.csv` 目前只有一條規則（`epoxy+phenol`），`functional_groups.csv` 只有兩個官能基。D65 要求第一版涵蓋半導體常見的熱固與光致交聯體系，分 A、B、C 三批。本卡做 **A 批**：把下列體系的官能基與反應規則加進資料表，並確認現有交聯第 0、1 層（Python 引擎的 `/crosslink/*`，D62）能處理；若現有引擎的結構（見「要做的事」第 5 步）不能處理某個體系，**只做資料表與清單，並在報告列出缺什麼**，不要自行大改交聯公式。依 D64：A 批相關規則一次建完、驗證一次、報告一頁。

A 批體系：

1. 環氧＋酚（已有，D25；酚醛清漆的酚羥基沿用，確認清漆、甲酚、雙酚、聯苯芳烷基、雙環戊二烯改質酚醛都能命中）
2. 環氧＋胺（一級、二級；脂肪與芳香）
3. 環氧＋酸酐（酸酐＋羥基開環成單酯酸，酸再與環氧開環；通常需要三級胺或咪唑催化）
4. 環氧＋氰酸酯（氰酸酯環三聚成三嗪環；氰酸酯與環氧可共反應成㗁唑啉或異氰脲酸酯，以書或文獻為準）
5. 酚醛清漆（novolac）＋六亞甲基四胺（HMTA）硬化（酚環鄰、對位空位形成亞甲基橋與苄胺橋）
6. 可溶酚醛（resol，鹼催化，帶羥甲基；羥甲基與酚環空位成亞甲基橋，羥甲基之間成二亞甲基醚橋，皆放出水或甲醛）
7. 陽離子光酸催化環氧與氧雜環丁烷（光酸產生劑照光放酸，酸催化環氧或氧雜環丁烷開環聚合；觸發條件是光，不是溫度）

## 要做的事

**一、官能基與規則（D22）**

1. 先列出每個體系需要的官能基（至少：酚環鄰／對位空位的芳香 C–H、羥甲基 `–CH2OH`（接在酚環上）、一級與二級胺的 N–H、酸酐、氰酸酯 `–O–C≡N`、氧雜環丁烷、HMTA 籠狀結構、已有的酚羥基與環氧）。每個官能基與規則依 D22：**先找已發表寫法**（RDKit 內建定義、Daylight SMARTS 範例、成熟開源套件、論文），記錄出處；找不到才自行撰寫並標「自行撰寫」；每條配**應命中**與**不應命中**的測試分子（`should_react`／`should_not_react`，可用 `+` 與 `|` 的既有格式）。酚醛類的測試分子要分別涵蓋：酚醛清漆寡聚物、可溶酚醛（含羥甲基）、甲酚、雙酚 A、聯苯芳烷基、雙環戊二烯改質酚；酚環的鄰、對位有無空位要有正反例。
2. 規則欄位：`reaction_type`、`catalyst_required`（照實填：無、三級胺、咪唑、光酸（需光酸產生劑與照光）、金屬離子等，依文獻）、`functionality_a/b`（每個官能基一次反應消耗幾個位點；例如一級胺 N–H 的官能度、酸酐、HMTA 的等效亞甲基數，**依書或文獻，不憑記憶**）、`byproduct`（水、甲醛、氨等，依文獻）。
3. `temp_min_c`／`temp_max_c`（S03：文獻記錄的典型反應溫度範圍）與 `bond_volume_change`（S05：文獻單位鍵體積變化值）：**找得到可引用的文獻或書值才填，並在 source 欄標出處（書名、表號、頁碼，或論文與表號）；找不到就留空並在 notes 寫「未找到可引用數值」，不要憑記憶填**。光酸催化規則的溫度欄寫觸發條件（光）而非溫度，不足的數值留空。
4. 所有新列 `review_status` 設為 `pending`（交使用者審，D17、D22 第 3 點）；不得自行設 `approved`。

**二、引擎能否處理（先判斷再做）**

5. 讀 `crosslink.py`、`layer1.py`，回答並在報告用一張表列出每個體系的結果：
   - 反應是兩種官能基配對（A＋B）還是**同種官能基自反應**（環氧／氧雜環丁烷陽離子開環、氰酸酯三聚、可溶酚醛的羥甲基自縮合）？
   - 一個分子內同時有兩種官能基（可溶酚醛的羥甲基與酚環空位）時，配對是否允許**同分子內**反應？
   - 有**多步反應或鏈增長**（酸酐先成酸再開環環氧；陽離子開環是鏈增長，不是逐步聚合）時，Miller-Macosko 凝膠點與當量公式是否適用？
   - HMTA 這類「一個分子提供多個等效反應位點，且需先分解」的成分，官能度怎麼表達？
   能直接用現有配對與公式處理的體系：把規則加進表、讓第 0 層命中、第 1 層照現有公式算。**現有引擎處理不了的體系：只加官能基與規則列（標 `pending`），第 1 層對它回報「此體系的凝膠點與當量計算尚未支援」與原因，不得套用不適用的公式硬算。** 不修改現有 Miller-Macosko 公式與既有測試。

**三、驗證（全部完成後只做一次）**

6. 新增資料列自動通過 `should_react`／`should_not_react` 測試（沿用現有資料表測試機制）。對每個體系挑一組有代表性的小配方（用 `docs/verification/` 已有的分子或規則表測試分子，不新增分子），跑第 0 層，產出「命中結果列表」`docs/verification/phase7-反應規則A-命中列表.md`：每條規則、對哪些成分的哪些位置命中、官能度與當量、第 1 層是否支援，**留空欄「使用者判定」**（D22 第 3 點，交使用者審化學正確性）。不做反向驗證與邊界探針。
7. 最少的單元測試：每個新規則一個命中、一個不命中；第 1 層遇到不支援體系回報原因而不是給數值（一個測試）。
8. 新增或修改 `src/data/` 的任何 CSV 後，**必須重新產生 `tests/golden/csv.json`**（P6B、P6E 兩次 golden-fresh 失敗都是漏了這一步），只新增對應案例，其他不動。新增測試字串一律用雙引號。
