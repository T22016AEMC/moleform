# 任務 P7-4a：配方成分密度輸入

編號：P7-4a
建立日期：2026-11-18
指派給：Claude Code

## 目標

P7-4 的固化收縮需要配方總體積，由各成分密度（混合密度，P6A）取得；介面沒有密度欄位，小分子成分沒有預測密度，所以以小分子為主的配方（包括 4A、4B）收縮回報 `missing`。使用者 2026-11-18 決定：**成分可手動輸入密度**。密度是文獻或供應商資料，不是使用者的實測 DSC，不違反 D02。依 D64：一次做完、報告三行。

## 前置條件（先讀這些）

- `docs/reports/P7-4-結果.md`（收縮需要哪些密度、缺值怎麼回報）、`docs/reports/P6A-結果.md`（混合密度端點的輸入）、`docs/reports/I01-結果.md`（配方成分如何送進引擎）、`docs/DECISIONS.md` 的 D02、D62、D64
- 配方成分的資料結構與儲存／載入（含舊配方檔如何載入）：只讀相關檔案；化合物庫（任務 012）若已有密度欄位，先確認
- 不要搜尋整個專案

## 要做的事

1. 配方每個成分新增**選填**的「密度（g/cm³）」欄位與「密度來源（文字）」欄位。成分是聚合物且未輸入密度時，沿用現有預測密度（不改現有行為）；小分子或預測密度缺值時，使用輸入的密度；兩者都沒有才回報 `missing`。輸入值在結果中標「使用者輸入」（不是預測），並顯示來源文字；輸入值必須是正的有限數，否則拒絕。
2. 化合物庫若已有密度欄位，成分選自化合物庫時預填，使用者可覆蓋。
3. **相容性**：舊的已儲存配方沒有這兩個欄位，載入時必須照舊運作（欄位視為空）；新欄位寫入儲存與載入、匯出匯入。
4. 混合密度（P6A）與固化收縮（P7-4）使用此欄位；其他計算不變。
5. UI 沿用現有成分列元件，只加欄位，不重做設計。欄位旁提示：「請填文獻或供應商資料的密度（g/cm³）；用於混合密度與固化收縮」。
6. 驗證一次：型別檢查；引擎 pytest；新增測試：有密度的小分子成分使收縮從 `missing` 變成有值、舊配方載入照舊、非正數密度被拒。用 4A 或 4B 的小分子成分填入任意**測試用**密度（測試檔內寫明為測試用，不寫進 `docs/verification/` 的正式結果）。不做反向驗證與邊界探針。
7. 報告 `docs/reports/P7-4a-結果.md` 三行以內。本機只跑本卡新增的測試、引擎 pytest、型別檢查；全部 TypeScript 測試與建置交給 CI。新增測試字串一律用雙引號。若動到黃金檔相關檔案，先重產所有受影響的 golden（只允許多出新項目、舊值不得變）。commit、push，用 PowerShell 查 CI，逐一確認 build、engine、golden-fresh 三個 job 成功。

## 不可更動的檔案或規則

- 不修改既有計算公式、既有預測密度的行為、資料表內容、既有測試、既有 CI job；不新增套件
- 不使用記憶中的密度數值；實測 DSC 值不進計算（D02）；引擎只在 127.0.0.1

## 完成標準（可檢查）

- [ ] 成分可輸入密度與來源，舊配方照舊載入，非正數被拒
- [ ] 小分子成分有密度時，混合密度與收縮可算；沒有時仍回報 `missing`
- [ ] 測試通過；CI 三個 job 逐一確認；已 commit 與 push
