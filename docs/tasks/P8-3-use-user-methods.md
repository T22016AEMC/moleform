# 任務 P8-3：配方面板接上使用者定義的算法（k 表 Vm、Bondi FFV 相對 Tg、自由體積）

編號：P8-3
建立日期：2026-11-19
指派給：Claude Code

## 背景（使用者 2026-11-19 回報）

配方面板的「物性（Python 引擎）」對使用者的材料幾乎全部回 `missing`：成分 Tg、混合 Tg、混合密度、混合介電、溶解性都算不出。原因是面板的成分 Tg 呼叫 `/tg`（書的基團加成），密度與介電走書的莫耳體積與極化基團表；稠環與特殊基團（茀、萘、螺環、環氧的 CH／CH2／O 等）書表沒有，就回缺基團。

但使用者早已定義過一套**通用**的算法（適用任何結構，不是針對特定化合物），且寫進決定與任務卡：

- 任務 038：Vm 以使用者的堆積係數 k 表為準（Vm＝VvdW／k）；Tg 用 Bondi FFV 差異法（Tg_B＝Tg_A − ΔFFV／Δα）
- 任務 038c 與 D61：Vm 來源順序為（1）k／Tg 表或使用者輸入的 k；（2）使用者輸入的密度；（3）D57 類別預設（標「類別預設，非材料值」）；（4）書的 Va
- 任務 036a 與 D57：使用者自己的自由體積法；共聚物是各單體的比例加權組合
- 使用者規則：MoleForm 要涵蓋一般半導體材料，使用者的材料只是其中一部分；**不為任何單一化合物客製**。使用者 2026-11-19 明確要求：不要為了單一化合物服務

這些算法在 TypeScript 已實作並驗證，Python 端有 `/vm`、`/free-volume`、`/relative-tg` 端點，但配方面板沒有按上述順序使用它們。本卡把面板接上，**做成任何結構都適用的流程**：不得在程式或資料表裡針對特定化合物（例如 6A、E3、P 樹脂）寫專用分支、專用名稱判斷或專用數值。

## 要做的事

**一、先查（只讀，結果寫進報告）**

1. 列出 `packing_coefficient_k.csv` 的所有材料名稱、結構對應方式（名稱或 SMILES）、有無 Tg 欄位，並說明表內材料涵蓋哪些**結構類別**（例如環氧、酚醛、聚醯亞胺、丙烯酸、聚矽氧等；以表中實際有的為準）。
2. 以一組**具代表性、涵蓋常見半導體材料類別**的測試結構（每個類別各一兩個；挑選依據寫進報告，不可只挑使用者自己的材料），逐一說明目前配方面板的成分 Tg、密度（Vm）、介電、HSP 各用哪一條路、回什麼、為什麼；以及改用 D61 的順序後哪些能算出。結果做成一張表，放報告。使用者回報的配方（6A／E3／丙二醇甲醚醋酸酯）只當其中一個實例，不作為設計依據。
3. 確認引擎 `/vm` 現在是否已按 D61 的順序（k 表、使用者密度、D57 類別預設、書 Va）取 Vm；沒有的話指出是哪一段沒接上。

**二、密度（Vm）接上 D61 順序**

4. 面板的成分密度、混合密度（`/mixture-density`）取成分密度時，一律按 D61 的順序：（1）k 表或使用者輸入的堆積係數 k；（2）使用者輸入的密度；（3）D57 類別預設；（4）書的 Va。每個成分的結果標出實際用了哪一條（k 表／使用者密度／類別預設，非材料值／書 Va），類別預設一律明顯標示。
5. 共聚物：依使用者定義，各單元的 Vm 與莫耳質量按莫耳分率加權（比例為 wt% 時先換算莫耳分率），再得到共聚物的密度；不再用「沒有提供 smiles」就放棄。任一單元取不到 Vm 時，整體回 `missing` 並指出是第幾個單元。
6. 新增或修改的資料表欄位只加不改；不修改 `packing_coefficient_k.csv` 的內容。

**三、成分 Tg**

7. 成分 Tg 維持原順序：先用書的基團加成；基團缺失時，**只在輸入條件齊全時**改用 Bondi FFV 相對 Tg（任務 038）：需要參考聚合物 A 的 Tg 與 k 表或使用者 k。條件不齊就維持 `missing`，原因寫清楚缺什麼（例如「需要參考聚合物 A 的 Tg」），並在面板告訴使用者可以提供什麼。不得自行挑參考聚合物。
8. 使用者自己的 DSC 資料只用於驗證，不進這條計算（D02）。

**四、其他**

9. 混合介電與書的極化基團表：仍只用書；缺基團時不從 k 表推介電。維持 `missing`，面板寫清楚，不改。
10. HSP（溶解性）：不改；聚合物 HSP 缺基團時維持缺值，並在面板說明這是書 Table 7.10 缺稠環基團。
11. 面板每一列在 `missing` 時，原因欄除了「缺什麼」，還要寫「使用者可以怎麼補」（填密度、選 k 表材料、輸入 k、提供參考聚合物 A 的 Tg）。若現有介面沒有輸入 k 的欄位，先回報，不要自行加版面；有現成欄位的就用現成的。
12. `docs/MODELS.md`、`docs/PLAN.md`、`docs/KNOWN_ISSUES.md` 以描述式編輯補註；`docs/DECISIONS.md` 不新增（用的是既有 D57、D61）。**不要整份覆寫任何文件。**

**五、驗證（全部完成後只做一次）**

13. 用步驟一的代表性測試結構組成幾個配方（含一個共聚物、一個含溶劑的配方）：回報密度、混合密度、成分 Tg 各自走哪條路、結果多少或缺什麼。再用一個書基團表全有的配方（例如 PMMA）確認結果與修改前逐位數相同。
14. 最少的單元測試：k 表命中、使用者密度優先於類別預設、類別預設有標示、共聚物莫耳分率加權密度（手算一例，附算式）、缺條件時 Tg 回 `missing` 並寫明缺什麼。不做反向驗證與邊界探針。
15. 報告 `docs/reports/P8-3-結果.md`，限一頁：缺口表（步驟一）、改了什麼、驗證結果、仍然算不出的項目與原因、需要使用者決定的事。
16. 本機只跑本卡新增測試、引擎 pytest、型別檢查；TypeScript 全部測試與建置交給 CI。新增測試字串一律用雙引號。新增或修改 `src/data/` 後先重產黃金檔（只允許新增、舊值不變）。盡量一次 push，push 後 CI 三個 job（build、engine、golden-fresh）逐一確認。
