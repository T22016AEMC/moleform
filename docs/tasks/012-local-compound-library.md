網站新增「我的化合物」卡片：使用者可以把目前的結構存起來、搜尋、載回、改名、刪除，並匯出成檔案備份或分享給同事、再匯入。資料只存在使用者自己的瀏覽器（D23），不經過任何伺服器。另外產出 Phase 2 的「使用者驗證清單」，讓使用者檢查結構與 3D 的化學結果。

## 要做的事

### A. 資料模型（`src/core/library/`，純 TypeScript）

1. 每筆化合物的欄位：
   - `id`（隨機唯一碼）
   - `name`（名稱，必填，1–100 字）
   - `canonicalSmiles`（RDKit canonical SMILES，必填）
   - `molfile`（使用者畫的 2D Molfile，保留原本的圖面排列；可空）
   - `notes`（備註，可空，最多 1000 字）
   - `createdAt`、`updatedAt`（ISO 時間）
   - **不存**分子量、官能基數量或當量（D09）
2. 化合物庫整體格式含 `schemaVersion: 1`，之後欄位變動時用來轉換舊資料。
3. 純函式（可在 Node 測試）：新增、改名、修改備註、刪除、以名稱或 SMILES 搜尋（不分大小寫、部分符合）、依 canonical SMILES 找重複、匯出成 JSON、匯入 JSON 並合併。

### B. 儲存（`src/ui/library/storage.ts`）

4. 用瀏覽器的 **IndexedDB** 儲存（容量比 localStorage 大），自己寫簡單的包裝，**不安裝套件**。
5. 所有讀寫都要處理失敗（例如無痕模式、使用者封鎖網站資料、空間不足）：失敗時畫面顯示「無法使用瀏覽器儲存，化合物不會被保存，請使用匯出功能備份」，其他功能照常運作。
6. 為了測試，儲存層要有介面，測試時改用記憶體版本。

### C. 畫面（`src/ui/library/CompoundLibrary.tsx`，風格用 `theme.css`，D34）

7. 「我的化合物」卡片放在「結構輸入」旁或下方（依畫面寬度排版，參考 CheMScutter 的響應式斷點）。
8. 功能：
   - **儲存目前結構**：結構必須通過任務 010 的驗證；輸入名稱後儲存。若已有相同 canonical SMILES 的化合物，提示「已有相同結構：{名稱}」，讓使用者選擇「仍要另存」或「取消」
   - **清單**：顯示名稱、canonical SMILES（過長時截斷，滑過顯示全文）、更新時間；可依名稱或時間排序
   - **搜尋**：輸入文字即時篩選名稱與 SMILES
   - **載入**：把該化合物送進結構輸入（有 Molfile 時用 Molfile，保留原本圖面）
   - **改名、編輯備註**
   - **刪除**：用畫面內的確認按鈕（例如按「刪除」後變成「確定刪除？」與「取消」），**不要用** `window.confirm` 或 `alert` 這類瀏覽器對話框
9. 卡片上顯示提醒：「資料只存在這台電腦的這個瀏覽器。清除瀏覽器資料、換電腦或換瀏覽器都會看不到，請定期匯出備份。」以及「上次匯出：{日期}」（從未匯出則顯示「尚未匯出」）。

### D. 匯出與匯入

10. **匯出 JSON**：全部化合物存成 `moleform-compounds-YYYYMMDD.json`（含 `schemaVersion`）。重用 `src/ui/download.ts`。
11. **匯入 JSON**：讀取檔案（在瀏覽器內，不上傳），逐筆驗證（SMILES 須能被 RDKit 解析）。合併規則：
    - `id` 已存在且內容相同 → 略過
    - `id` 已存在但內容不同 → 以 `updatedAt` 較新者為準
    - `id` 不存在 → 新增
    - 無效的列 → 略過並記錄原因
    - 完成後顯示「新增 N 筆、更新 N 筆、略過 N 筆（原因…）」
    - `schemaVersion` 不認得 → 不匯入，顯示說明
12. **匯出 SDF**：全部化合物存成一個 SDF，每筆的標題列是名稱，另附 `MoleForm_Name`、`MoleForm_Notes` 欄位，方便用其他化學軟體開啟。
13. **匯入 SDF**（批次）：每筆建立一個化合物，名稱取標題列或 `MoleForm_Name`，沒有就用「匯入 N」；驗證規則同第 11 點。檔案上限沿用任務 010 的 10 MB。

### E. 測試（`tests/library/`）

14. 只檢查程式行為（D17）：新增、改名、刪除、搜尋、重複偵測；JSON 匯出再匯入後內容完全相同；合併規則四種情況各一例；無效 SMILES 被略過並有原因；不認得的 `schemaVersion` 被拒絕；SDF 匯出再匯入後名稱與 canonical SMILES 不變；儲存層失敗時不拋出未處理的錯誤。

### F. Phase 2 使用者驗證清單（2.9）

15. 寫一個腳本（放 `scripts/verification/`），用 Node 對下列分子執行結構驗證與 3D 計算（種子 42），把**程式輸出**整理成 `docs/verification/phase2-輸出.md`：
    - 分子：乙醇 `CCO`、環氧丙烷 `CC1CO1`、苯酚 `Oc1ccccc1`、雙酚 A `CC(C)(c1ccc(O)cc1)c1ccc(O)cc1`、BADGE `CC(C)(c1ccc(OCC2CO2)cc1)c1ccc(OCC2CO2)cc1`、L-丙胺酸 `C[C@@H](C(=O)O)N`、反式 2-丁烯 `C/C=C/C`、BF₃ `FB(F)F`
    - 每個分子輸出：canonical SMILES、驗證結果與提示、構象數、是否經力場最佳化、最低能量構象中**每一種鍵型**（例如 C–C、C–O、C=C、芳香 C–C、C–H、O–H）的鍵長範圍（Å），以及環氧環的鍵角（有環氧環的分子）
    - 檔案開頭寫明：「以下為程式輸出，未經化學判斷。請使用者依文獻或經驗檢查是否合理（D17）。」
    - **不要**在輸出中加入任何文獻參考值或「正常／異常」的判斷
16. 新增 `docs/verification/README.md`：說明這個資料夾的用途（每個 Phase 結束時放一份程式輸出給使用者檢查），以及如何重新產生輸出。

### G. 檢查、文件、提交、推送

17. 依序執行 `npm run typecheck`、`npm test`、`npm run build`，全部通過。
18. 在 `docs/KNOWN_ISSUES.md` 新增一列：「瀏覽器儲存可能被清除（使用者清除資料、瀏覽器空間回收、無痕模式），化合物庫不是永久保存；處理方式：畫面提醒定期匯出備份」。
19. 提交（訊息：`本機化合物庫與 Phase 2 驗證清單（任務 012）`），推送方式依 `AGENTS.md`。
20. 測試時若啟動了背景伺服器，結束前自己關閉；無法關閉就在報告列出連接埠。

## 不可更動的檔案或規則

- 資料只存在使用者的瀏覽器；不得傳到任何伺服器或外部服務（D23）
- 不得儲存或顯示分子量、官能基數量或當量（D09）
- 不得使用 `window.confirm`、`alert`、`prompt` 等瀏覽器對話框
- 驗證清單只放程式輸出，不得加入化學判斷或文獻值
- 不安裝新套件；需要時先問使用者
- 不得修改 CheMScutter 與 `moleform-handoff`
- 不得修改 git 或認證設定；不得 force push
