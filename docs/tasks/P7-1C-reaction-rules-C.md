## 目標

D65 的 C 批：壓克力／甲基丙烯酸酯、硫醇–烯。做法與 P7-1A、P7-1B 完全相同（D22、`pending`、數值無來源就留空、引擎處理不了就回報「尚未支援」與原因、不支援清單只在 Python），完成後 PLAN 7.1 整體勾選。依 D64：一次做完、驗證一次、報告半頁。

C 批體系：

1. 壓克力／甲基丙烯酸酯（含丙烯醯胺、乙烯基、苯乙烯類，依文獻有明確寫法者）的自由基加成聚合：熱起始劑或光起始劑（光自由基產生劑）觸發。這是**鏈增長**，不是逐步聚合；每個雙鍵的官能度、起始劑的角色（催化劑式觸發，不是被計量消耗的反應物）依文獻。
2. 硫醇–烯：硫醇（–SH）加成到碳碳雙鍵（烯、烯丙基、乙烯基醚、降冰片烯、丙烯酸酯依文獻），自由基逐步加成（光或熱起始）。這個體系是**逐步增長**，可能能用現有 A＋B 配對與公式處理，由你依文獻判斷並在報告說明。
3. 壓克力與環氧、異氰酸酯等其他官能基的雜化體系（例如含環氧的丙烯酸酯，同一分子兩種官能基）：只做官能基命中，不另加跨體系規則。

## 要做的事

1. **官能基與規則**（同 P7-1A／B 第一部分）：先找已發表寫法並記出處，找不到才自行撰寫並標「自行撰寫」；每條配應命中與不應命中的測試分子（丙烯酸酯與甲基丙烯酸酯要有正反例，苯乙烯、丙烯醯胺、乙烯基醚、烯丙基、降冰片烯、硫醇與硫醚要能區分；環氧丙烯酸酯同時命中兩種官能基要有一個例子）；`review_status` 一律 `pending`；溫度與 `bond_volume_change` 找不到可引用來源就留空並在 notes 說明。光起始劑與熱起始劑用 A 批光酸產生劑的同一種「催化劑配對」表示法，顯示「催化劑配對（不計當量）」。已有官能基（環氧、酚、胺等）不得重複定義。
2. **引擎能否處理**（同 P7-1A 第 5 步）：用一張表說明壓克力鏈增長、硫醇–烯各自能不能用現有第 0、1 層處理。鏈增長不適用逐步聚合的 Miller–Macosko 凝膠點，**回報「尚未支援」與原因，不得硬算**；硫醇–烯若確能照 A＋B 逐步增長處理，依現有公式算並在 notes 說明適用條件。不修改現有交聯公式。
3. **驗證（一次）**：新增資料列的應命中／不應命中測試通過；每個體系挑一組代表性小配方（用 `docs/verification/` 已有分子或規則測試分子，不新增分子）跑第 0 層，產出 `docs/verification/phase7-反應規則C-命中列表.md`（格式同 B 批，「使用者判定」欄留空）。最少的單元測試：每條新規則一個命中、一個不命中；不支援體系回報原因一個。不做反向驗證與邊界探針。
4. **golden**：新增或修改 `src/data/` 後，先檢查並重產所有受影響的 golden 檔（B 批範圍：`csv.json`、`crosslink.json`、`layer1.json`、`molGraph.json`，其他會列出官能基的黃金檔先檢查），逐案例比對只允許多出新項目、舊值不得變，push 前自查，避免第一次 CI 失敗。新增測試字串一律用雙引號。
5. **收尾**：報告 `docs/reports/P7-1C-結果.md`，限半頁；`docs/PLAN.md` 7.1 勾選並補註 A、B、C 三批完成，以及「待補規則：馬來醯亞胺自聚、ene 後續共聚、苯并㗁嗪＋環氧、封端異氰酸酯解封端（本機文獻無明確反應式，另卡找文獻補）」；`docs/MODELS.md` 若有規則說明則補一段。
6. 本機只跑本卡新增的測試、引擎 pytest、型別檢查；全部 TypeScript 測試與建置交給 CI。commit、push，用 PowerShell 查一次 CI（GitHub 匿名 API 被限流時，等額度重置後再查一次，不要反覆重試）。
