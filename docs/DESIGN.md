# 介面設計規則（DESIGN）

介面風格直接沿用 CheMScutter（DECISIONS D34）。所有變數定義在 `src/ui/theme.css` 的 `:root`，數值取自 CheMScutter 的 `src/ui/analysis.css`、`src/ui/results/results.css`（原樣，不自行調整）。

## 規則

**新增畫面一律使用 `theme.css` 的變數；需要新顏色或尺寸時先加進 `theme.css` 與本檔。** `src/ui/` 內除 `theme.css` 外的 CSS 檔不得硬寫色碼。

## 檔案分工

- `src/ui/theme.css`：變數
- `src/ui/base.css`：全域 `body`、標題、`button`、`input`、`select`、`label`、`.card`、`.error`、`.number`
- `src/ui/components/components.css`：頁首、頁尾、結果顯示元件
- `src/ui/crosslink/crosslink.css`：交聯結果（判定區塊、配對表、反應原子標記圖）；反應原子的強調色一律取 `--color-accent`
- `src/ui/workbench/workbench.css`：配方工作台的兩欄版面、成分列、右欄可收合區塊、彈窗（任務 018，D45）

## 配方工作台的版面（任務 018，D45）

- 分頁：配方工作台（預設）、分子工具、化合物庫。
- 寬度 **1280px 以上**：左欄輸入、右欄結果並排；右欄 `position: sticky`，自己捲動，左欄捲動時它不跟著跑。**小於 1280px**（`@media (max-width: 1279px)`，直接寫在 `workbench.css`）：改為輸入在上、結果在下，不固定。
- 右欄四個區塊（組成、交聯第 0 層、交聯第 1 層、理論配比與比例掃描）可展開／收合，預設全部展開，狀態只存在畫面中。
- 彈窗：Esc 或點暗色區域關閉；開啟時焦點移進彈窗，關閉後回到原本的按鈕。Ketcher 的 iframe 只在需要時載入（彈窗的 Ketcher 分頁、成分詳細的「用 Ketcher 編輯結構」、分子工具分頁顯示時），同一時間最多一個。焦點在 Ketcher 畫布內時，Esc 不會傳到彈窗外層（瀏覽器對 iframe 的限制），請用「✕」或點暗色區域關閉。

## 3D 構象的自訂值（任務 011）

下列數值與名稱是 **AI 工具實作時自訂、不來自文獻**，使用者已確認保留（2026-10-29）。要改請同時改程式與本節。

### 構象合併閾值

- 位置：`src/core/conformer/session.ts` 的 `MERGE_RMS_ANGSTROM`，目前 **0.1 Å**。
- 意義：MMFF94 最佳化後，兩個構象**重原子之間全部原子對距離**的均方根差在此以內，視為同一構象並合併（保留先產生者）。用距離矩陣比較，與旋轉、平移無關。
- 其他自訂值：預設構象數 5、每次增加 5、上限 30、固定種子 42、產生器嘗試次數上限 60（`session.ts`）。

### 3D SDF 欄位（`src/core/conformer/export.ts`）

全部構象各一筆，欄位如下；能量欄位只在有 MMFF94 能量時出現。

| 欄位 | 意義 |
|---|---|
| `Conformer` | 構象序號（從 1 起算）；有能量時依能量由低到高排序（1 為最低能量），未最佳化時為產生順序 |
| `Seed` | ConformerGenerator 的亂數種子（固定 42）；同結構同種子結果可重現 |
| `Optimized` | `MMFF94`：這個構象經 MMFF94 最佳化；`no`：未經力場最佳化（MMFF94 缺參數，K07） |
| `MMFF94_Energy_kcal_per_mol` | MMFF94 總能量，單位 kcal/mol（K08：以 MMFF94 Validation Suite 比對確認）。只適合比較**同一分子**的構象，不同分子之間不可比 |
| `Relative_Energy_kcal_per_mol` | 相對於本檔所有構象中最低能量者的差，單位 kcal/mol；最低者為 0 |

### 構象選單的說明文字

能量最低的構象標示「最低能量（建議使用）」，產生 3D 後預設顯示它；選單旁附說明：「相對能量相差約 1–2 kcal/mol 以內的構象，在室溫下會同時存在；本結果為 MMFF94 力場對單一分子在真空中的估算，未考慮溶劑與周圍分子。」（使用者指定的文字，不得改寫。）

## 交聯第 0 層的判定規則（任務 016）

依每個反應配對兩邊的「每分子平均反應官能度 f」做計數判定（f = 位點數 × 規則官能度；聚合物再乘聚合度 DP）：

| 條件 | 判定 |
|---|---|
| 兩邊都 f ≥ 2，且至少一邊 f > 2 | 具形成網路的結構條件 |
| 兩邊都 f = 2 | 具鏈延長的結構條件 |
| 有一邊 f < 2（例如 f = 1） | 具封端的結構條件；若另一邊是聚合物則為具接枝的結構條件 |
| 有一邊 f 未知（聚合物缺少分子量） | 無法判定 |

整個配方：任一配對具形成網路的結構條件，即判定「配方具形成網路的結構條件；是否凝膠與交聯程度見第 1 層」；否則依序為「具鏈延長的結構條件」、「具封端／接枝的結構條件」、無反應。第 0 層只看結構條件，不代表一定凝膠（使用者審核意見，2026-10-29）。這是依官能度的計數判定，不判斷反應會不會實際發生（D17）；結果畫面不顯示官能基數量與當量（D09），數量只列在 `docs/verification/phase4-輸出.md`。

## 聚合物 mol% 與分子量輸入（任務 019，D46、D47）

- 任務 013 報告第 3 節「含連接點 `*` 的成分使 mol% 整區不輸出」的規則，**聚合物有分子量時已由 D46 取代**：預設以整條鏈（Mn）計，結果區可切換「以鏈計／以重複單元計」，並在表格下附註「聚合物 mol% 以整條鏈（Mn）計」或「聚合物 mol% 以重複單元計」。切換只影響 mol% 顯示，不影響交聯計算。
- 含連接點但缺分子量（沒有 Mw、Mn、DP）的成分，仍依任務 014 的規則，該區不輸出 mol%，並說明原因。
- 區域單位選 mol% 時：聚合物以目前選擇的基準換算為質量（鏈：質量 = mol% × Mn；重複單元：質量 = mol% × M_unit）；此時切換基準會改變各成分的質量比。
- 分子量輸入：主要為 Mw＋PDI（PDI 留空顯示「使用預設 PDI = 2」）；可切換為 Mn＋PDI 或 DP＋PDI。Mn 或 DP 沒有 PDI 時顯示「PDI 未填，使用預設值 2」。輸入欄旁顯示的換算值（Mw、Mn、DP_n、DP_w）屬使用者輸入的輔助，不在結果區顯示（D09）。
- 第 0 層判定規則表中「聚合物缺少分子量」現為「聚合物缺少分子量（Mw、Mn、DP 皆未填）」。

## 目標 Solid Content 與 Liquid 用量（任務 020 後續）

- 填入目標固含量後：Liquid 區的單位選單與「該區總重」停用／隱藏，各成分用量欄改為**唯讀**，顯示程式算出的用量並標示「依目標固含量計算」；區域標題下註明基準。
- 基準：Solid 質量已知（單位 g，或有填 Solid 總重）→ 溶劑以 g 顯示；未知 → 每 100 份固體，溶劑以重量份顯示（單位標「份」），並在區域說明註明「以每 100 份固體為基準（重量份）」。
- 一種溶劑：直接算出用量，不需填值。多種溶劑：每列另有「比例」輸入（重量份，空白視為 1），總量由程式依目標分配。
- 填了目標後，Liquid 成分用量空白不觸發「尚未填完用量」；清空目標回到手動輸入（單位、總重欄恢復）。
- 右欄「組成」與 Solid Content 依計算後的用量顯示（Solid Content 等於目標）；重量份基準時質量欄位的單位為「重量份」。
- 配方檔記錄 `liquidFromTarget: true`；舊配方沒有此欄位，仍可讀取（核心不套用自動計算，Liquid 用量與「目標 Solid Content 反推」照原規則）。畫面載入有目標的舊配方時，因目標欄非空而進入自動計算模式，存檔後才寫入旗標。

## 聚合物端基欄位（任務 022，D50）

- 單元清單（或均聚物的輸入方式）上方有「端基 1」「端基 2」兩個下拉選單：「不填（未計入端基）」（預設）、端基清單 27 項（依資料表順序，顯示名稱與 SMILES）、「自訂 SMILES」（出現 SMILES 輸入框）。選好的端基顯示縮圖。
- 欄位下方說明：「端基只填鏈盡頭多出來的部分；已經畫在重複單元裡的原子不要重複填。」
- 均聚物與共聚物都有；分子工具、加入成分彈窗、成分詳細彈窗三處一致。分子量輸入欄旁的換算值（DP_n、DP_w、Mn、Mw）使用含端基的式子，附註依端基填寫狀況顯示。
- 單元或端基的檢查有錯誤時，錯誤訊息顯示在欄位上方，欄位仍保留可修改。
- 成分詳細彈窗：有填的端基在單元圖旁各一張小圖，標示「端基 1／端基 2」並標出反應原子；交聯第 0 層的反應原子標記圖也包含端基。

## 骨架範本選單（任務 023，D51）

- 聚合物設定的單元清單上方有「從骨架範本填入」下拉選單（6 項，顯示名稱）；分子工具、加入成分彈窗、成分詳細彈窗三處一致。分子工具的聚合物設定卡片沿用既有規則：結構含連接點時才出現，所以選單也要等結構含 `*` 才看得到。
- 選單旁一行說明：「範本只填入結構；分子量（Mw、PDI 等）請依產品資料填寫。」
- 選了範本：單元清單換成範本的單元（一種），兩個端基換成範本的端基（有對應 id 選該項，沒有就用自訂 SMILES）；分子量欄位（輸入方式、數值、PDI）不動。選了之後先顯示「會取代目前的單元與端基，確定嗎？」，按「確定取代」才套用，「取消」不改任何東西。
- 套用後的狀態和使用者自己輸入的完全一樣，可以再改；配方檔與化合物庫不記錄用了哪個範本。
- 交聯第 1 層結果附註：使用低分子量修正時，在分布附註後加「低分子量：以 n = 0 分子與較重成分兩成分近似」。

## 聚合物單元清單與成分詳細彈窗（任務 020 後續）

- 單元清單格式統一（分子工具、加入成分彈窗、成分詳細彈窗）：每列有縮圖、SMILES 欄、比例、刪除按鈕；只有一種單元時不顯示清單（與均聚物相同），也就沒有可刪除的列。第一列的 SMILES 是成分本身的結構（唯讀）；只有成分詳細彈窗可以刪除第一列（成分結構換成下一種單元）。
- 成分詳細彈窗上方的大結構圖：共聚物改為所有單元並排，每張圖標示「單元 N、比例」並標出反應原子。

## 目標固含量的基準選擇與單元的 Ketcher 繪圖（任務 021，D49）

- 目標欄旁的「目標對應：全部／扣除標記成分」只在 Solid 區至少一個成分勾了「揮發／分解」時顯示，預設「全部」；取消所有揮發標記後選擇隱藏，基準自動回到「全部」。右欄：選了哪一種，該 Solid Content 等於目標，另一種照原公式顯示。目標超過扣除標記後的最大可達值時，在目標欄下顯示錯誤（例如「扣除標記成分後，Solid Content 最高只能到 80%（目標 85%）」）；等於最大值時 Liquid 為 0，沒有錯誤。
- 共聚物單元清單中，第二列以後的每一列有「用 Ketcher 畫」按鈕，另有「＋新增單元（用 Ketcher 畫）」；第一列維持唯讀；端基欄位不加 Ketcher。分子工具、加入成分彈窗、成分詳細彈窗三處都有。
- 每個彈窗或頁面最多一個 Ketcher（D28）：畫單元時借用該處的 Ketcher，暫時卸下原本的結構繪圖（分子工具：StructureInput 的 Ketcher 釋放，之後以目前結構還原；兩個彈窗：主結構的 Ketcher 卸下，之後以最近一次的結構還原）。面板標示「正在畫：單元 N」，按「套用到單元 N」才寫回該列的 SMILES；套用前用同一套連接點規則（D48）檢查，錯誤指出第幾個單元。編輯已有 SMILES 的列時先載入該列結構（SMILES 先由 RDKit 轉成 Molfile，K09）。
- Ketcher 有尚未套用的修改時，切換到別的單元、取消、關閉彈窗都要先確認。離開「分子工具」分頁會收掉單元繪圖（釋放 Ketcher）。
- 端基選 EG10（羥基）時，欄位下方提示：「接在芳香環上的酚羥基請改選 EG11（對位酚）或 EG12（鄰位酚）；EG10 只會被當成一般羥基。」只是提示，不阻擋、不自動更換。

## Ketcher 未套用內容不得悄悄丟失（任務 021 後續）

- **離開「分子工具」分頁**（使用者 2026-10-30 決定）：單元繪圖有未套用的修改 → 先跳確認「單元 N 在 Ketcher 裡有尚未套用的修改，離開會放棄這些修改。確定要離開嗎？」（「放棄並離開」／「取消」）；取消就留在分子工具、單元繪圖與修改都還在。沒有未套用的修改 → 直接收掉單元繪圖、釋放 Ketcher，不詢問。
- **借用 Ketcher 畫單元之前**：原本的結構繪圖畫布有「尚未驗證」的筆畫（使用者修改後，到匯出並經 RDKit 驗證完成之前；偵測用 Ketcher 的變更事件）→ 先確認「畫布上有尚未驗證的修改，改畫單元後會還原成最近一次驗證過的結構。確定要繼續嗎？」（「繼續」／「取消」）。沒有這種筆畫 → 直接借用，不詢問。
- 三個地方（分子工具、加入成分彈窗、成分詳細彈窗）判斷方式一致；彈窗內原有的「關閉前確認」不變。加入成分彈窗與成分詳細彈窗還原主結構時，使用畫布最近一次匯出的 Molfile（即使驗證沒通過）。
- 沒有未套用的修改時不多出任何確認；單元之間切換、取消、關閉的確認維持任務 021 的做法。狀態轉移規則在 `src/ui/polymer/drawingState.ts`（純函式，有測試）。
