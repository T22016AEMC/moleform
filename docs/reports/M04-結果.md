- **引擎端點**：`POST /polymer/repeat-unit`、`/end-groups`、`/copolymer`、`/convert`、`/distribution`（`value/unit/source/status`；輸入無效回 400；僅 127.0.0.1，未接介面）。
- **黃金檔**：`scripts/golden/export-polymer-{repeatUnit,endGroups,copolymer,convert,distribution}.ts` → `tests/golden/polymer-*.json`，共 **366 個案例**（111／70／73／72／40），錯誤路徑（連接點數量、編號、無法解析、比例合計、Mn ≤ M_ends、低分子量修正無解）的輸出也比對。Python 全部通過，**`tolerance_cases` 為 0**（浮點逐字相同）。引擎 pytest 共 6683 passed；`npm run typecheck` 通過。TS 全部測試與建置交給 CI。
- **R2**：連接點＝原子序 0 的原子，依 RDKit 原子索引順序（不重排）；分子式用 `AddHs` 後逐原子計數，Hill 順序與 TS 逐字相同（含 `#<原子序>`）。連接點在環上、支鏈上、同一原子、雜環與稠環、`[*:n]` 編號都有案例，一致。

- **捨入**：這五個模組**沒有 `Math.round`**。JS 的捨入出現在錯誤訊息的 `Number(x.toFixed(n))`（比例合計 6 位、`M_ends` 3 位）：正好 .5 時 JS 進位、Python `format` 是銀行家捨入（例：90.0078125 → JS `90.007813`、Python `90.007812`）。Python 用 `Decimal` 精確展開實作 `js_to_fixed`，`roundhalf/` 案例（copolymer、convert 共 17 個）逐字相同。

## 與 TS 不一致或需注意處

- 兩個 TS 既有特性照重現、已列入 `docs/migration-known-issues.md`：**K06** 映射編號 ≥ 100 被讀成 0（TS 從 Molfile 文字切欄位）；**K07** 帶電連接點（`[*+]`）讓 TS 拋出 WebAssembly 例外（Python 拋 `RdkitCallError`，HTTP 回 400）。**D03**：Python 只接 SMILES，不接 Molfile／JSON（M00 的決定，介面送的都是 SMILES）。
- Python 不用 `Descriptors.MolWt` 而用 `_CalcMolWt`：`Descriptors` 會匯入 numpy，在引擎的處理執行緒中匯入會卡住（實測第一個請求逾時），兩者是同一個 C++ 函式。
- 沒有需要修改 TS 計算檔、沒有需要超過 1e-12 的容差、沒有原子順序／分子式／分子量不一致。
