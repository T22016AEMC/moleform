# 報告 001：測試 RDKit.js 的 3D 能力

日期：2026-10-29

## 結論（先講）

官方 `@rdkit/rdkit` 2026.9.1 只附 `RDKit_minimal`，**沒有 3D 功能**：不能產生 3D 座標、不能做 MMFF94／UFF、沒有多構象與能量，只有 2D 座標。這與預期差很多，也代表 DECISIONS P01 的條件「RDKit.js 全部支援 → 純前端」**不成立**，需要你決定。（任務單的「需要先問使用者」第 2 項：測試結果與預期差很多。）

## 改了哪些檔案

- 新增 `experiments/rdkit-3d/`：`package.json`、`package-lock.json`、`run.js`、`README.md`、`node_modules/`（只裝 `@rdkit/rdkit@2026.9.1`）、`output/`。
- `docs/PLAN.md`：0.3 勾選，並註記結果。
- `docs/KNOWN_ISSUES.md`：K01「狀態」改為已驗證結果。
- 沒有在專案根目錄建立 `package.json`，沒有建立 Vite／React 骨架，沒有安裝其他套件。

執行方式（在 `experiments/rdkit-3d/`，PowerShell）：`npm install; npm run test3d`。腳本不報錯、不支援項目已記錄為不支援。

## 測試環境與事實（任務單第 4 點）

| 項目 | 結果 |
|---|---|
| 套件 | `@rdkit/rdkit` 2026.9.1（與 CheMScutter 相同），RDKit 版本字串 2026.09.1 |
| 授權 | BSD-3-Clause（套件 `package.json` 的 license 欄位） |
| 套件內容 | 只有 `RDKit_minimal.js`、`RDKit_minimal.wasm`、`RDKit_minimal.d.ts`（`files` 欄位僅列這三個） |
| WASM 檔案大小 | 7,379,879 bytes（約 7.0 MB） |
| 初始化時間 | 約 68 ms（Node v24.22.0、本機） |
| 每個分子產生座標耗時 | 加氫＋2D 座標＋輸出 molblock，單次約 0.8 ms（20 次平均）；首次約 2–15 ms。**這是 2D 座標的耗時，不是 3D** |

## 測試結果（逐項）

測試分子：乙醇 `CCO`、環氧丙烷 `CC1CO1`；兩者結果相同。

| # | 檢查項目 | 結果 | 使用的 API／說明 |
|---|---|---|---|
| 1 | 產生 3D 座標（ETKDG 或等價） | **不支援** | 只有 `Mol.set_new_coords()`／`get_new_coords()`（RDKit／CoordGen 的 2D 版面）。加氫後輸出的座標 z 全為 0（zRange = [0, 0]），不是 3D。沒有 embed、距離幾何或 ETKDG 相關函式 |
| 2 | MMFF94 最佳化；缺參數退到 UFF | **不支援** | 沒有任何力場函式（module 與 Mol 物件都沒有 mmff／uff／optimize 名稱）。因此「MMFF 缺參數退 UFF」也無法測 |
| 3 | 多構象與每個構象能量 | **不支援** | 沒有構象列表、`embed_multiple_confs`、能量 API |
| 4 | 輸出含 3D 座標的 MOL 與 SDF | **部分支援** | `Mol.get_molblock()`、`get_v3Kmolblock()` 可輸出 MOL，SDF 可由 molblock 加 `$$$$` 自行組成；**但座標只有 2D**。已輸出 `output/*_2D_with_H.mol`／`.sdf`（檔名標明 2D），沒有 3D 檔案 |
| 5 | 鍵長、鍵角、二面角 | **RDKit.js 不支援，可自行計算** | 沒有 Geometry API。`run.js` 示範由 molblock 座標用純函式算出（鍵長 1.50、鍵角、二面角）；示範值來自 2D 座標，只證明可算，沒有化學意義 |
| 6 | 記錄 API 名稱 | 如上表 | 完整 API 清單在 `output/results.json` 的 `api.allMolMethods`、`api.allModuleFunctions` |

另確認（`output/results.json`）：Module 提供的函式為 `get_mol`、`get_qmol`、`get_rxn`、`get_mcs_*`、`molzip`、`prefer_coordgen`、`RGroupDecomposition`、`SubstructLibrary` 等，無 3D 相關項目。

## 關於 minimal 版本（使用者要求註明）

- 3D 功能**不在** `RDKit_minimal` 中；npm 上的官方 `@rdkit/rdkit` 2026.9.1 只發布這一個版本（沒有別的 wasm 檔案可換）。
- 因此「換成哪個官方檔案就有 3D」**這次無法給出答案**：npm 套件內沒有。要在瀏覽器得到 ETKDG／力場，可能做法是自行用 RDKit 原始碼編譯含這些功能的自訂 MinimalLib（需要 Emscripten 工具鏈與編譯設定），但我**沒有驗證可行性、檔案大小與授權影響**，不能保證。
- 其他 JS／WASM 化學函式庫我沒有測試，也不在任務範圍（任務單規定除 `@rdkit/rdkit` 外不安裝其他套件）。AGENTS.md 提醒避免 GPL 套件（例如 Open Babel）。

## 遇到的問題

- 第一次執行失敗：`require.resolve('@rdkit/rdkit/package.json')` 被套件的 `exports` 擋住，已改為直接用路徑讀取 package.json。
- PowerShell 5.1 預設編碼會讓 `results.json` 內的中文在終端機顯示成亂碼；檔案本身是 UTF-8，內容沒有問題。
- `experiments/rdkit-3d/node_modules` 約數 MB，測試完可以刪除，不影響報告；重跑時 `npm install` 即可。

## 對架構的建議（由使用者決定，P01）

事實：2D 繪圖（Ketcher）、SMILES、結構驗證、官能基 SMARTS、子結構比對、描述子（RDKit.js 有 `get_descriptors`）在純前端都做得到。**缺的只有小分子 3D**（PLAN Phase 2 的 2.5–2.7，以及 PLAN 4.4／7.3 中用到 3D 位阻的部分）。

| 選項 | 內容 | 優點 | 缺點 |
|---|---|---|---|
| A. 純前端，3D 降級 | 不做 3D；Phase 2.5–2.7 改為只顯示 2D（Ketcher），鍵長、鍵角、二面角不做 | 架構最簡單、符合 D23／D24 靜態網站、無伺服器 | 失去 spec 的 3D 功能（旋轉、構象能量、量測）；反應位點相對活性的「3D 空間位阻」部分只能降級（PLAN 7.3 標為參考趨勢，影響較小） |
| B. 純前端 + 自行編譯含 3D 的 RDKit MinimalLib | 自行把 ETKDG／力場編進 WASM，仍可離線、純前端 | 保持靜態網站與 RDKit 一致 | 需要自行編譯與維護；檔案會變大；可行性與耗時**未驗證**；若引入其他來源的程式碼，需先確認授權（AGENTS.md） |
| C. 3D 另用 Python 服務（Node + Python 混合） | 後端用 Python RDKit（ETKDG、MMFF94／UFF、多構象能量） | 功能完整、最成熟 | 違反目前 D23（不使用伺服器）的精神，需要部署與維護伺服器，需更新 D23／D24；3D 前端顯示仍需另外選擇函式庫 |
| D. 2D 座標之外自行用簡單幾何估算 | 不建議 | — | 不是真正的構象，可能誤導化學判斷（與「標示為理論構型」的原則衝突） |

我的建議：先選 A，讓 Phase 1–4 不被 3D 卡住；3D 若你認為必要再評估 B 或 C。這只是建議，不是決定。

## 需要使用者決定的事

1. P01 架構：A（純前端、3D 降級）、B（自行編譯含 3D 的 RDKit WASM）或 C（Python 服務做 3D）。
2. 若選 A，是否修改 PLAN Phase 2.5–2.7 與 spec 的 3D 章節（我沒有改，需另開任務單）。
