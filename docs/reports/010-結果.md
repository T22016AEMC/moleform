## 4. 結構驗證行為（`src/core/structure/validate.ts`）

`validateStructure(RDKit, input)` → `{ valid, empty, canonicalSmiles, molblock, problems[] }`；`problems` 每項為 `{ level: 'error' | 'info', code, message }`。

- 空白 → `empty: true`，一條 info「尚未輸入結構。」，不是錯誤
- SMILES 語法錯（`C1CC`、`xyz`）→ `UNPARSABLE`；語法正確但價數／芳香性錯（`C(C)(C)(C)(C)C`、`c1cccc1`）→ `SANITIZATION_FAILED`（以「不做價數檢查時能否解析」區分）
- 含 `>`（反應 SMILES）、反應檔（`$RXN`）→ `REACTION`；SMARTS 特徵（`[C,N]`、`C~C`、`[C;R]`…，語法不是 SMILES 但能當 SMARTS 讀）、Molfile 查詢原子／鍵 → `QUERY`
- 含 `*` → 合法，附一條 info「含連接點 *，聚合物重複單元功能在 Phase 5 提供」
- 輸出的 Molfile 一律為 **V2000、2D 座標**；SMILES 輸入會產生 2D 座標，Molfile 輸入已有的 2D 座標不改動，3D 座標會重新產生 2D

## 7. 遇到的問題與處理

1. **Ketcher 自己匯入 SMILES 會把 `[*:1]` 變成 R 基團標籤**（R1、R2），匯出成 `R#`；純 `*` 則可正常顯示與匯出。處理：SMILES 含 `*` 時，改送 RDKit 產生的 Molfile（連接點寫成 `*`，映射編號保留），Ketcher 就顯示為 `*` 原子。詳見 K09。這是任務單「Ketcher 無法顯示或匯出連接點 `*`」的相近情況，但 `*` 本身可顯示、匯出，所以我沒有停下來，改用上述做法並在此回報。
2. RDKit 把虛原子寫成 `R`，Ketcher 讀到會變成 `R#`。處理：匯出的 Molfile 把連接點改寫成標準的 `*`（V2000 規格內），Ketcher 與 RDKit 都能原樣來回。
3. RDKit 的 `get_molblock()` 遇到 Ketcher 的 abs 立體標記（V3000 `MDLV30/STEABS`）會自動輸出 V3000，違反「V2000」。處理：改用 `get_v2Kmolblock()`（V2000，立體保留），已加測試。
4. Molfile 第一行（名稱）可以是空白，不可對 Molfile 做 `trim()`，否則整份檔案位移；已修正並由測試涵蓋。
5. `has_coords()` 在 RDKit.js 的回傳：0 無座標、2 為 2D、3 為 3D（與直覺的 1／2 不同），程式依此判斷是否重新產生 2D 座標。
6. 本機有兩個我啟動的背景 Node 程序（`vite preview` 埠 4173、`vite dev` 埠 5174）在驗證後想結束時，被自動權限檢查擋下（結束其他程序的指令），所以**可能還在執行**，請您手動關閉（工作管理員結束 `node.exe`，或重開機）。無頭 Edge 已由驗證腳本自行關閉。
7. `npm ci` 時出現 `deprecated` 警告（`intersection-observer`、`deep-diff`）：屬於 Ketcher 的間接相依，版本不可更動；`npm audit` 回報 0 個弱點。
8. 建置仍有 `node:fs`／`node:crypto` externalized 警告（RDKit 的 JS 內含 Node 專用分支，K 的任務 008 備註），瀏覽器實測 RDKit 載入與運作正常，可視為無害。
