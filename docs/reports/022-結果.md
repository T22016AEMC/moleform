## 測試結果（全部通過）

- `end_groups.csv` 27 列通過格式檢查；缺出處、`*` 不是一個、id 重複、標題列不符、RDKit 解析失敗都報錯並指出列與欄位。
- 手算範例：單元 `[*:1]CC([*:2])c1ccc(O)cc1`（120.15）、端基 1 正丁基、端基 2 氫、Mn 3000：M_ends = 58.12、DP_n = 24.4848（未計端基時 24.97）；每分子酚羥基 = DP_n；輸入 DP 反推 Mn = 3000；程式值與程式自己的分子量代入式子差小於 1e-9。
- 單元無環氧、兩端都是 EG08：每條鏈環氧基 = 2，兩個虛擬成分都是 2（Mw 1000、6000 皆然）。
- Mn ≤ M_ends 報錯「Mn 必須大於端基質量合計（M_ends = 58.124）」；只填一端附註「端基 N 未填，未計入」；端基 SMILES 0 個或 2 個 `*` 報錯並指出端基 1 或 2。
- 凝膠點：M_unit 200、每單元 2 個官能基、M_ends 200、端基 2 個官能基、Mw 6000／PDI 1.8 → M₁ = 2000、M₂ = 10000，f₁ = 20、f₂ = 100，f(Mw) = 60；兩成分近似的凝膠點 = 單一成分 f = 60，差小於 1e-10。
- 存檔／讀檔、化合物庫 JSON 與 SDF 來回、內容比較、舊檔讀成兩端不填。

## 遇到的問題

- **EG10（羥基）等需跨過 `*` 才能辨識的端基**：羥基是否為酚羥基取決於 `*` 另一側接的是否為芳香碳，目前的 SMARTS 不跨過 `*`，所以認不得（已寫入 `KNOWN_ISSUES.md` K11，未另寫新規則）。EG14（胺基）、EG15（羧酸）等因官能基表尚無對應官能基，也認不得。
- 前述前置文件差異（無 021 報告與 D48）。
- 單元或端基分析失敗時舊程式會把欄位整個換成錯誤訊息（任務 020 起存在），已一併修正。

## 請使用者在瀏覽器確認

1. 下拉選單：「不填（未計入端基）」、27 項（依資料表順序，顯示名稱與 SMILES）、「自訂 SMILES」（出現輸入框）；選好後顯示縮圖。
2. 欄位下方的說明文字「端基只填鏈盡頭多出來的部分；已經畫在重複單元裡的原子不要重複填。」；分子工具、加入成分彈窗、成分詳細彈窗三處都有。
3. 換算值隨端基改變：例如單元 `[*:1]CC([*:2])c1ccc(O)cc1`、端基 1 正丁基、端基 2 氫、Mn 3000，輸入欄旁 DP_n ≈ 24.5（未填端基約 25.0）；只填一端顯示「端基 N 未填，未計入」，兩端都填不顯示附註。
4. 自訂 SMILES 填錯（沒有 `*` 或兩個 `*`）顯示「端基 1／2：…」錯誤，且欄位仍可修改。
5. 成分詳細彈窗：端基小圖標示「端基 1／端基 2」並標出反應原子（例如 EG08 的環氧基）；交聯第 0 層的反應原子標記圖也有端基。
6. 把端基設為 EG08（兩端），重複單元不含環氧：配方與第 1 層能算出（環氧基來自端基）。
7. 存進化合物庫、重新載入，端基還原；存配方、重新載入，端基還原。
8. 舊配方（沒填端基）載入後結果不變。
