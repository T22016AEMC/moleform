## 3. 反應 SMARTS 測試採用的方式（E-12）
RDKit.js minimal 有執行反應的 API（`Reaction.run_reactants`），所以**直接執行反應**：`should_react` 必須產生至少一組產物，`should_not_react` 必須沒有產物。兩個分子會依 `A,B` 與 `B,A` 兩種順序各試一次，任一順序有產物就算「會反應」（避免反應 SMARTS 模板順序與 `group_a`／`group_b` 順序不同而誤判）。反應物數量與模板不符造成例外時視為沒有反應。

## 4. 遇到的問題
- 任務單未規定哪些欄位必填，我只照任務單明文規則檢查。**未列為必填、因此可空的**：`functionality_a`、`byproduct`、`name_zh`（溶劑）、`cas`、`smiles`（溶劑）、`bond_volume_change`；其餘（見 `docs/DATA.md`）必填。
- 我額外加了幾條任務單沒寫的檢查：`functionality_a／b` 須為正整數；`temp_min_c`、`temp_max_c` 須同時填或同時空（任務單「空時兩者都要空」的延伸）；`reactive_atom_maps` 須為整數；同一 `method` 內同一 `group_id` 只能有一個 `group_name`；group_contributions 與 solvents 的 `value`、`unit` 必填。若不要請告訴我。
- `load.ts` 目前只被測試引用，尚未被網站程式引用，所以 CSV 還沒實際進入網站 bundle（`?raw` 匯入已寫好，一旦 UI 引用 `load.ts` 即隨建置打包）。
- 報告中的「第 N 列」是 CSV 記錄編號（標題為第 1 筆），欄位內含換行時不等於 Excel 的列號以外的行號；一般情況與 Excel 列號一致。
