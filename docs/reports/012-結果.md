## 3. 行為說明

- **儲存**：只有「結構輸入」目前結構有效時才能儲存；名稱 1–100 字。存入的 Molfile 是驗證後的 2D Molfile（保留圖面排列）。已有相同 canonical SMILES 時顯示「已有相同結構：{名稱}」，可選「仍要另存」或「取消」。
- **載入**：有 Molfile 用 Molfile，否則用 SMILES，送進 Ketcher 並重新驗證（3D 卡片會跟著更新）。
- **刪除**：按「刪除」變成「確定刪除？」與「取消」。全程沒有使用 `window.confirm`、`alert`、`prompt`。
- **儲存失敗**（無痕、封鎖網站資料、空間不足）：畫面顯示「無法使用瀏覽器儲存，化合物不會被保存，請使用匯出功能備份」；清單仍留在畫面（本次工作階段可用、可匯出），其他功能照常。
- **匯出 JSON**：`moleform-compounds-YYYYMMDD.json`，含 `schemaVersion`；用既有的 `src/ui/download.ts`。「上次匯出」日期**只在匯出 JSON 時更新**（SDF 不含 id 與時間，不算備份）；如要連 SDF 也算請告知。
- **匯入 JSON**：逐列驗證欄位與 SMILES；合併規則照任務單。補充：id 相同、內容不同、但匯入的 `updatedAt` 與現有相同或較舊 → 保留現有並略過（原因「內容不同但現有的較新或一樣新」）。匯入時 SMILES 會重新用 RDKit 轉成 canonical。不認得的 `schemaVersion` 整檔拒絕。完成後顯示「新增 N 筆、更新 N 筆、略過 N 筆（原因…）」。
- **匯出 SDF**：標題列＝名稱，附 `MoleForm_Name`、`MoleForm_Notes`。SDF 資料欄位不能含空行，所以備註中的空行在 SDF 內會被合併（JSON 不受影響）。沒有 Molfile 的化合物會先由 SMILES 產生。
- **匯入 SDF**：每筆建立新化合物（新 id，不做重複合併）；名稱取 `MoleForm_Name`、標題列，都沒有用「匯入 N」；超過 100 字會截斷。檔案上限 10 MB（JSON 也套用）。
- 匯入檔案用 `File.text()` 在瀏覽器內讀取，不上傳。

## 5. 請使用者在瀏覽器確認的清單

1. 儲存兩個結構（例如乙醇、BADGE），各輸入名稱
2. 重新整理網頁後仍在
3. 搜尋（輸入名稱片段、輸入 SMILES 片段）；切換排序（更新時間／名稱）
4. 載入回結構輸入，確認 Ketcher 圖面與原本相同、3D 卡片可重新計算
5. 改名、編輯備註
6. 刪除：按「刪除」→「確定刪除？」／「取消」兩條路徑
7. 再存同一結構（可換不同寫法，如 `OCC`）時出現「已有相同結構：{名稱}」，並可「仍要另存」或「取消」
8. 匯出 JSON；確認檔名 `moleform-compounds-YYYYMMDD.json`，「上次匯出」更新為今天
9. 刪掉全部，匯入該 JSON 復原；再匯入一次，應顯示全部略過
10. 匯出 SDF，用其他化學軟體開啟，確認名稱與結構
11. 在無痕視窗開啟：應看到儲存失敗的提示，其他功能（結構輸入、3D）正常，且仍可匯出
12. 縮小視窗到手機寬度，確認卡片排版
13. 開啟 `docs/verification/phase2-輸出.md`，依文獻或經驗檢查 8 個分子的輸出（報告不做化學判斷，D17）

## 6. 遇到的問題與限制

1. **沒有在真實瀏覽器實測**：我只跑了自動測試與建置。`createIndexedDbStorage` 對真實 IndexedDB 的讀寫、卡片畫面與 Ketcher 載入流程沒有實際執行過，只有「IndexedDB 不存在或開啟失敗時不拋錯」有測試。請特別檢查第 5 節 1、2、4、11 項。
2. 名稱排序用 `localeCompare(…, 'zh-Hant')`，中英文混合時的先後依瀏覽器語系，測試只檢查英文名稱之間的順序。
3. 驗證腳本載入 TypeScript 的方式：Node 無法直接匯入無副檔名的 `.ts`，所以腳本用 Vite 的 `ssrLoadModule` 載入 `src/core/`（Vite 已是既有相依套件）。
4. 驗證輸出的鍵長取構象 1：有 MMFF94 能量時是最低能量構象；BF₃ 未最佳化，取產生的第一個構象，檔內已註明。芳香鍵以 OpenChemLib 的芳香判斷分類。
5. 測試時沒有啟動任何背景伺服器，沒有需要關閉的連接埠。
