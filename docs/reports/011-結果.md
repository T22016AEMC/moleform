## 3. 行為說明

- **resources.json**：Worker 內以 `Resources.registerFromUrl()` 載入，網址用 Vite `?url` 取得。`openchemlib` 的 `exports` 沒有開放 `dist/resources.json` 子路徑，所以用相對路徑 `../../node_modules/openchemlib/dist/resources.json?url`。只在第一次按「產生 3D」才載入，之後重複使用。
- **種子**：固定 42，畫面顯示。同種子兩次結果完全相同（有測試）；「5 個再加到 6 個」與「一次 6 個」結果相同（有測試）。
- **構象數**：預設 5；「產生更多構象」每次再加 5，上限 30；產生器無法再提供新構象時提示（乙醇只有 1 個，沿用任務 005 的結論：羥基氫轉動不算可旋轉鍵）。
- **原子順序**：輸入為任務 010 的 RDKit Molfile。測試確認 3D 結果中重原子索引、元素、重原子間的鍵與輸入完全一致，新增的氫接在後面（乙醇、BADGE、L-丙胺酸、苯酚）。畫面編號 = 索引 + 1。
- **不支援 3D**：含 `*`（顯示「含連接點的重複單元不提供 3D（3D 只用於單體與小分子，D05）」）、無效或空白（說明文字）；重原子 > 100 個時先顯示「分子較大，3D 計算可能需要較長時間」，按「仍要計算」才開始。
- **MMFF94 缺參數（K07）**：捕捉 `ForceFieldMMFF94` 的錯誤，整批改用未最佳化的初始構象，顯示「未經力場最佳化（MMFF94 不支援此結構中的元素或原子型）」，不顯示能量。BF₃（`FB(F)F`）有測試。
- **取消**：結束 Worker，下次重新建立；之後的「更多構象」會重新計算（種子固定，結果相同）。
- **「更多構象」的 Molfile**：沿用第一次送去計算的 Molfile。因為 Ketcher 載入後會重新排版 2D 座標，Molfile 文字會改變；3D 結果的身分改用 canonical SMILES 判斷，座標重排不會讓 3D 結果被清掉。（我在無頭瀏覽器測試時遇到這個問題並修正。）
- **能量顯示**：用任務 008 的 `ResultValue`：模型「MMFF94（OpenChemLib JS）」、可信度「直接計算」、附統一備註與出處。顯示的是**目前選的構象的相對能量**（最低者 0）。

## 4. 構象合併的判斷方式與閾值

每個構象經 MMFF94 最佳化後，取**重原子的全部原子對距離（距離矩陣）**，與已保留的每個構象比較：均方根差 **≤ 0.1 Å** 視為同一構象並合併（保留先產生者）。用距離矩陣是因為它與旋轉、平移無關，不需要先疊合。只比重原子，所以只有甲基氫等不影響重原子骨架的差異會被合併。產生器嘗試次數上限 60 次（30 × 2），避免重複很多時一直跑。

閾值 0.1 Å 是我設的，**不是來自文獻**；是否合適（太寬會合併掉真正不同的構象、太窄會留下重複）請使用者判斷。BADGE 實測：第一批 5 個沒有合併，再加 5 個時合併 1 個。BADGE 的構象 2 與 3 相對能量相同（都是 0.16 kcal/mol）但幾何不同（沒有被合併），可能是對稱等價構象，未再深究。

## 8. 請使用者實測與確認的清單

**2.5a：在自己的電腦實測（請記下數字）**

1. `npm run build` 後 `npm run preview`（或部署後的網站），載入 BADGE：`CC(C)(c1ccc(OCC2CO2)cc1)c1ccc(OCC2CO2)cc1`
2. 按「產生 3D」，記下畫面「本次計算」顯示的「產生構象」、「力場最佳化」與「整體等待」秒數
3. 計算期間試著捲動頁面、修改上方的 SMILES，看是否卡住
4. 按「產生更多構象」，再記一次耗時
5. 判斷耗時是否可接受（D33）；不可接受就依 D33 降級為不顯示 3D

**其他確認**

6. 切換 Ball-and-Stick、Stick、Space-Filling 三種樣式
7. 勾選「顯示原子編號」，確認從 1 起算，與結構的原子順序相符
8. 依序點選 2 個原子看鍵長、3 個看鍵角、4 個看二面角，並用已知值（例如 C–C、C–H 鍵長，sp3 碳鍵角約 109°）粗略對照；「清除量測」可重置

11. 輸入含硼的結構（例如 `CB(C)C` 或含 BF₃ 的錯合物），確認顯示「未經力場最佳化…」且不顯示能量
12. 輸入 `*CC*`，確認 3D 卡片顯示「含連接點的重複單元不提供 3D…」
13. 構象閾值 0.1 Å 與「乙醇、環氧丙烷只有 1 個構象」是否可接受

## 9. 遇到的問題與需要使用者決定的事

遇到的問題：

1. 第一次無頭測試時 3D 卡片計算到一半被清空：Ketcher 載入後把 2D 座標重新排版，Molfile 文字改變，3D 卡片以 Molfile 判斷「結構改變」而取消計算。已改用 canonical SMILES 判斷並沿用第一次的 Molfile。
2. `openchemlib` 的 `exports` 沒有開放 `resources.json`，不能用套件子路徑 `?url`，改用相對的 `node_modules/...` 路徑（`vite build` 與型別檢查都通過）。
3. 3Dmol.js 的程式碼含直接 `eval`（建置警告，來源是 3Dmol 內部）。目前主網站沒有 CSP（只有 Ketcher 子頁有），不影響；**若日後主網站加上禁止 `unsafe-eval` 的 CSP，3Dmol 需要重新評估**。
4. 建置警告 chunk 超過 500 kB：3Dmol（約 580 kB）與 conformer worker（約 1.09 MB）；它們都是按需載入，不在首頁。
5. 無頭瀏覽器是軟體 WebGL，畫面截圖僅作功能確認。
6. 我啟動的靜態伺服器（連接埠 4180）與無頭 Edge 是背景程序；Edge 已由腳本結束，伺服器如果還在執行請手動結束（結束其他程序的指令可能被權限檢查擋下）。

需要使用者決定：

1. 3D 耗時是否可接受（2.5a，D33），以及是否勾選 PLAN 2.5–2.7。
2. 能量單位只在中性 C/H/N/O/F/Cl 分子驗證過。畫面對其他元素（S、P、Si、Br、I、離子）仍照常顯示 kcal/mol；是否維持，或在這些結構上加註「單位未驗證」，或擴大比對範圍？
3. 構象合併閾值 0.1 Å（第 4 節）是否適用。
4. OpenChemLib 對乙醇、環氧丙烷只給 1 個構象（不轉動羥基氫）是否可接受。
5. 3D MOL／SDF 的種子與能量欄位名稱（`Conformer`、`Seed`、`Optimized`、`MMFF94_Energy_kcal_per_mol`、`Relative_Energy_kcal_per_mol`）是我自訂的，是否需要調整。
6. 本任務未改動：K09、其他 PLAN 項目。PLAN 2.5–2.7（含 2.5a、2.5b）未勾。2.5b 的單位比對已完成，如要勾 2.5b 請告知。
