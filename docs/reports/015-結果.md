## 3. M_unit 的計算方式

RDKit 的平均分子量（`amw`）。RDKit 把虛原子 `*` 的質量視為 0，且各原子的氫數照重複單元原樣計算（連在 `*` 上的碳不會因 `*` 被移除而多補氫），所以等於「把 `*` 移除、不補氫」的重複單元平均分子量。例：`*CC*` 為 C₂H₄。分子式另以補上隱含氫後逐原子計數（不計 `*`）得出，Hill 順序。已寫入 `docs/DATA.md`。

連接點規則（`analyzeRepeatUnit`）：恰好兩個；少於或多於兩個、兩個連在同一個原子、連接點沒連到原子、兩個連接點直接相連、編號不是 `[*:1]`＋`[*:2]`（順序不拘）或兩個都未編號 → 中文錯誤。未編號時依出現順序視為 1、2。

### 程式輸出（P、E 的重複單元）

| 成分 | 重複單元去除 `*` 後的分子式 | M_unit（g/mol） | 換算 |
|---|---|---|---|
| P（雙酚茀–萘甲醛型） | C36H24O2 | 488.586 | Mn = 6000 → DP = 12.28 |
| E（PGMA 型） | C7H10O3 | 142.154 | DP = 21 → Mn = 2985.2；Mn = 3000 → DP = 21.10 |

E 的 DP = 21 換算出的 Mn（約 2985）與使用者提供的 Mn ≈ 3000 約略一致；以上只是程式輸出，不判斷化學。

## 4. 行為說明與我自行決定的地方

- **`schemaVersion` 維持 1**：新增的 `polymer` 是選用欄位，沒有它的舊版檔案照舊可讀（化合物庫、配方庫、單一配方皆然），所以沒有升版；有測試。若您希望升為 2，請告知。
- **「均聚物設定」卡片**：「結構」分頁目前結構含 `*` 時出現，位置在「結構輸入」與「我的化合物」之間。連接點不符規則時顯示錯誤（不顯示 Mn／DP 欄）；符合時顯示 Mn／DP 單選＋輸入欄，另一個值顯示在欄旁（例：`DP ≈ 21.1（未計入端基）`、`Mn ≈ 2,985 g/mol`）。M_unit 不顯示。
- **化合物庫儲存**：含 `*` 的結構一律視為聚合物，必須通過連接點規則並填好 Mn 或 DP 才能儲存（否則顯示原因）；這個檢查在「已有相同結構」確認之前。清單標示「聚合物　Mn … / DP …」；「改名／備註」可同時修改 Mn／DP；載入聚合物時，Mn／DP 一併還原到「均聚物設定」。以往若有含 `*` 的舊紀錄（無 polymer），仍可讀，視為一般化合物。
- **SDF**：聚合物以重複單元 Molfile 輸出，附 `MoleForm_Type=polymer` 與 `MoleForm_Mn` 或 `MoleForm_DP`；匯入時若有 `MoleForm_Type=polymer`，需有連接點與 Mn 或 DP，否則該筆略過並說明原因。
- **配方**：含 `*` 的成分顯示「聚合物」標籤與 Mn／DP 輸入欄（從化合物庫或「結構」分頁加入時帶入已填的值）。質量相關換算照常；mol% 沿用任務 014（整區不輸出；單位選 mol% 時仍報 U02 錯誤）。聚合物成分以 Mn 作為每分子質量傳入核心，但核心不用它算 mol%（程式註解已寫明，且有測試：傳入 Mn 與否結果完全相同）。配方存檔含聚合物設定。
- 3D：聚合物不提供 3D，沿用任務 011 的說明（含連接點的結構不能產生 3D）。
- 結果區不顯示分子量（D09）；無頭檢查確認結果區沒有「分子量」「g/mol」。Mn／DP 只出現在輸入欄旁當輸入輔助。

## 7. 遇到的問題

- 任務單的 `[*:1]CC` 等 1 個連接點案例沒問題；我自己寫的第一個測試案例（`*C.*[*:1]`）其實有 3 個連接點，已改正。
- RDKit 的 JSON 輸出不含原子映射編號，所以編號改由 V2000 Molfile 的映射欄讀取。
- 儲存時原本「已有相同結構」確認會先於聚合物檢查，無頭檢查發現後已調換順序。
